## Отчет по Лабораторной Работе №3: Автоматизация выполнения скриптов с помощью Cron в Docker

### Цель работы

Основной целью данной работы было изучение и практическое применение инструментов автоматизации для периодического запуска Python-скриптов. В ходе работы требовалось настроить планировщик задач **cron** внутри изолированного окружения **Docker** для автоматического выполнения скрипта получения курсов валют, разработанного в лабораторной работе №2.

### Структура проекта

Для выполнения задания была создана новая директория `lab03`, в которую были скопированы и адаптированы файлы из предыдущей работы. Финальная структура каталога `lab03` выглядит следующим образом:

```
lab03/
│
├── currency_exchange_rate.py  # Скрипт для получения курса валют
├── cronjob                    # Файл с расписанием задач для cron
├── Dockerfile                 # Инструкция для сборки Docker-образа
├── docker-compose.yml         # Файл для запуска контейнера
├── entrypoint.sh              # Скрипт инициализации для контейнера
└── readme.md                  # Документация по проекту
```

### Описание файлов и компонентов

- **`currency_exchange_rate.py`**: Скрипт из `lab02`, который был незначительно модифицирован. В него была добавлена возможность получать URL API-сервиса из переменной окружения (`API_URL`), что необходимо для сетевого взаимодействия между Docker-контейнерами.
    
- **`cronjob`**: Текстовый файл, содержащий определения задач для `cron`. В нем настроены два задания:
    
    1. **Ежедневно в 6:00**: Запуск скрипта для получения курса MDL к EUR за предыдущий день.
        
    2. Еженедельно в 17:00 (пятница): Запуск скрипта для получения курса MDL к USD за неделю до текущей даты.
        
        Весь вывод команд перенаправляется в лог-файл /var/log/cron.log.
        
- **`Dockerfile`**: Набор инструкций для сборки Docker-образа на основе `python:3.11-slim`. Dockerfile выполняет следующие шаги:
    
    1. Устанавливает `cron`.
        
    2. Копирует необходимые файлы (`currency_exchange_rate.py`, `cronjob`, `entrypoint.sh`) внутрь образа.
        
    3. Устанавливает Python-зависимости (`requests`).
        
    4. Настраивает `cron`, помещая файл с задачами в системную директорию `/etc/cron.d/`.
        
    5. Назначает `entrypoint.sh` в качестве стартового скрипта контейнера.
        
- **`docker-compose.yml`**: Файл для оркестрации, который упрощает процесс сборки образа и запуска контейнера. Он определяет сервис `cron-runner`, передает в него необходимые переменные окружения (`API_URL`) и монтирует локальные папки (`data` и `error.log`) в контейнер для удобного доступа к результатам.
    
- **`entrypoint.sh`**: Вспомогательный shell-скрипт, который выполняется при старте контейнера. Его основная задача — подготовить окружение для `cron` (создать лог-файл, передать переменные окружения) и запустить сам `cron` в основном режиме (`foreground`), что предотвращает немедленное завершение работы контейнера.
    

### Процесс настройки и запуска

1. **Запуск API-сервиса**: Первым шагом был запущен Docker-контейнер с API-сервисом из лабораторной работы №2.
    
2. **Сборка и запуск Cron-контейнера**: С помощью команды `docker-compose up --build -d` в директории `lab03` был собран новый образ и запущен контейнер `lab03_cron_runner` в фоновом режиме.
    

### Проверка и отладка

Для проверки корректности работы системы был выполнен ручной запуск задачи внутри контейнера с помощью команды `docker exec`.

**Команда для PowerShell:**

PowerShell

```
docker exec lab03_cron_runner python3 /app/currency_exchange_rate.py MDL EUR "$((Get-Date).AddDays(-1).ToString('yyyy-MM-dd'))"
```

В ходе отладки были выявлены и устранены следующие проблемы:

- **Ошибка `404 Not Found`**: Изначально API-сервис был недоступен. Проблема была решена полным перезапуском (`docker-compose down` и `up`) контейнера API.
    
- **Синтаксис команды**: Команда `date` из Linux-окружения была адаптирована для PowerShell.
    

После успешного ручного теста был получен результат `✅ Данные сохранены...`, и в локальной папке `data` появился соответствующий JSON-файл, что подтвердило полную работоспособность системы.

### Проверка созданных файлов

Скрипт сохраняет результаты в папку `data` в корне проекта. Благодаря настройке `volumes` в `docker-compose.yml`, эта папка синхронизирована с вашим компьютером. Просто проверьте содержимое папки `data/` — там должны появляться новые JSON-файлы после выполнения задач.

docker exec -it lab03_cron_runner bash
